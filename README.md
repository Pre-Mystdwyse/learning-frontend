## О проекте:
Интерактивный дашборд с элементами RPG. Проект разработан для демонстрации навыков проектирования сложной бизнес-логики, работы с глобальным состоянием и построения масштабируемой архитектуры. Основной упор сделан на надёжность, производительность и чистоту кода. (UI/UX реализован базово, так как основной фокус проекта сделан на хардкорную логику, оптимизацию рендеринга и архитектурные паттерны)

## Технологический стек:
* Core: React 19, TypeScript 7 (ES2025), Vite 8;
* State management: Zustand 5, TanStack Query;
* Routing: React Router v6;
* Style: Tailwind CSS v4;
* Testing: Vitest, React Testing Library;
* Code quality: ESLint (flat config), Prettier, Steiger (FSD Linter)

## Ключевой функционал:
- **Кузня:** Покупка экипировки с проверкой баланса и генерацией уникальных инстансов предметов;
- **Инвентарь:** Управление предметами с возможностью продажи и **отмены последних действий (Undo)**;
- **Доска квестов:** Асинхронная загрузка заданий, выполнение квестов в реальном времени с фоновыми таймерами;
- **Профиль героя:** Редактирование характеристик, мировоззрения и навыков;

## Инженерные решения:

* Архитектура:
    *  проект построен по `FSD`;

    *  архитектурные границы контролируются линтером `Steiger (Rust)`;

*  State management:
    *  для сторов использован `Zustand`, прописана транзакционость для предотвращения состояния гонки и дюпа предметов при быстрых кликах;
    *  насроил `custom middleware`, которое перехватывает функцию `set` для создания снимка стейта, необходимого для функции отмены последних действий;
    *  для выборочного сохранения прогресса в `LocalStorage` использованы `persist` и `partialize`;
    
*  Оптимизация:
    *  Таймеры квестов отвязаны от жизненного цикла React. Для плавной анимации прогресс-баров используется нативный **Web Animations API** (`Element.animate()`) в связке с `transform: scaleX`, что переносит расчеты на GPU и исключает пустые ре-рендеры;
    *  Прописана защита от утечек памяти путём удаления при размонтировании таймеров, интервалов, объектов анимации и тач-ивентов;
    *  Оптимизация рендеринга списков через `useMemo` и `React.memo` (больше для демонстрации умения пользоваться, чем реальной прибавки к производительности);

* Fullstack и интеграция:
    *  разработал собственный REST API сервер на `Node.js` + `Express` и задеплоил на отдельный хостинг;
    *  разделил проект на `client state` (`Zustand`) и `server state` (`TanStack Query`) с дедупликацией запросов и кэшированием;
    *  логика фильтрации, обработка query-параметров и имитация серверных задержек с ошибками реализованы на стороне бэкенда;
    *  перенёс на сервер алгоритм Фишера-Йетса и там же создаю Set из хранящихся данных для оптимизации поиска;
 
* Работа с данными и форма:
    *  использовал `React Hook Form` + `Zod` для создания неуправляемых (через `register`) и управляемых (через `<Controller>`) компонентов форм со строгой рантайм-валидацией;
    *  есть перехват ввода на лету;
    *  использую `UUIDV7` для генерации ID предметов, потому что в отличие от полного рандома в V4, в V7 первая часть ID - это текущее время, что нужно для предотвращения фрагментации B-дерева индексов в будущей БД;
    *  использовал `as const` для сужения типов массивов, что гарантирует безопасную привязку статических данных UI к строгой схеме валидации Zod на этапе компиляции;
    
* Адаптивный UI и микро-UX:
    *  Mobile-First с полной адаптивностью под любые экраны;
    *  использовал CSS Grid (`auto-fit`, `minmax`) для резинового инвентаря и CSS Columns для плиточной верстки квестов на лад Masonry Layout;
    *  Кастомная реализация Touch-событий для закрытия модальных окон свайпом вниз (знаю, что для этого лучше использовать готовые библиотеки, мне просто было интересно прописать самим, чтобы понять принцип);
    *  написал `useModalBehavior`, который как следит за Esc для закрытия, так и компенсирует ширину скроллбара при блокировке скролла, ~~и именно поэтому свечка и совершает свои колебания~~ и именно поэтому страница не дёргается;

* Инфраструктура и code quality:
    *  настроил абсолютные импорты на уровне сборщика и tsconfig, при этом использую новый `Rolldown` вместо старого `Rollup` бандлера для оптимизации сборки;
    *  использую в проекте современный ESLint flat config, а также Prettier с плагином `prettier-plugin-tailwindcss`. все настройки форматирования зафиксированы на workspace-уровне;
    *  модальные окна и меню для мобильных устройств сделаны с помощью `createPortal` на уровне `body` воизбежание конфликтов z-индексов и багов с `backdrop-filter` у родительских контейнеров;
 
* Тестирование:
    *  настроил среду тестирования с помощью `Vitest` и `jsdom`;
    *  написал unit-тесты для проверки чистых функций бизнес-логики;
    *  написал UI/integration-тесты с помощью `React esting library` и `user-event` для проверки взаимодействия пользователя с компонентами.

 ## Локальный запуск
 
<details>
<summary>Нажмите, чтобы развернуть</summary>
  
Требование: Node.js 20+

Проект состоит из клиентской (Vite) и серверной (Express) частей. для локального запуска потребуются 2 терминала.

  
1. Клонировать репозиторий:
   ```bash
   https://github.com/Pre-Mystdwyse/learning-frontend.git
   ```
2. Запуск бэкенда (терминал 1):
   ```bash
   cd server
   npm install
   npm run dev
   ```
   сервер запустится на http://localhost:3000
3. Запуск фронтенда (терминал 2):
   из корня проекта:
   ```bash
   npm install
   npm run dev
   ```
   Либо запустить для локальной сети:
   ```bash
   npm run dev -- --host
   ```
   ссылки будут выведены в терминале, переход через CTRL + LMB;

</details>
